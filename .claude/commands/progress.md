# /progress

AI has no memory between sessions. This ledger is the only thing that answers *"which module
was I in, and what does it still owe"* without rediscovering the system from the source — which
is expensive, slow, and **reaches a different conclusion each time** (rule 9).

---

## THE TWO SIDES

| | |
|---|---|
| **WRITE** | `kb/90-ephemeral/tien-do/<module>.json` — one file per module. You touch **only your module's file** |
| **READ** | `kb/90-ephemeral/tien-do.md` — **one file**, generated by `make kb`. Never edit it |

One shared file that several agents write is the shape `ROUTING.md` §3 forbids outright: the
later write silently erases the earlier one. One file per module means two agents never open
the same file, so **there is no lock — and therefore no lock left jammed when an agent dies.**

`<module>` is a top-level deployable directory (`service-identity`, `web-admin`, `core`,
`proto`, …), or **`_chung`** for work that belongs to no single unit — running the real
migrations, cleaning git history, sweeping a whole class of hooks.

---

## THE SHAPE OF AN ITEM — five keys, no more

```json
{
  "id": "grpc-server",
  "viec": "Server gRPC của identity",
  "trang_thai": "chua_lam",
  "bang_chung": "không có service-identity/internal/grpc — kiểm 2026-09-20",
  "no_confirm": [],
  "tiep_theo": "dùng lại interceptor ở core/grpcx; đọc ADR 0012 trước khi thêm RPC"
}
```

| Key | Rule |
|---|---|
| `trang_thai` | `chua_lam` · `dang_lam` · `xong` · `treo`. Nothing else |
| `bang_chung` | `file:line`, or a command that was run and its result. **Mandatory for `xong`** |
| `no_confirm` | Question **numbers** from `kb/00-foundation/open-questions.json`. A link, never a copy — and never a question already `DECIDED` |
| `tiep_theo` | The next concrete step, naming the file to open |
| `menu` *(optional)* | Slug, or list of slugs, of `docs/ui-ux/NN-<slug>.md`. A link to the spec, checked by `progress_guard` R8 and `tools/tien_do.py`. It is the second axis: `tien-do.md` "Theo menu" gathers every module's items for one menu, and `python tools/tien_do.py --menu "<tên>"` prints one — what `/develop-*` reads first |

**`treo` vs blocked:** `treo` means *we chose not to do it*. Blocked is `no_confirm` being
non-empty — derived from the link, never a separate flag, for the same reason rule 10 derives
overdue instead of storing it.

## PROCEDURE

### Reading — before starting work

1. `kb/90-ephemeral/tien-do.md` — one read gives every module, and which questions block what.
2. Your module's JSON if you are about to write to it.

Do **not** start from the source tree. That is what this file exists to save.

### Writing — before the session ends

1. Open `kb/90-ephemeral/tien-do/<module>.json` **from disk, now** — not from what you read an
   hour ago. Another agent may have added an item since.
2. `Edit` the item you changed. Do not rewrite the whole file: `progress_guard` blocks a write
   that makes an existing item disappear, and that block is the last line of defence, not the
   first.
3. Finished something → set `trang_thai` to `xong` **and fill `bang_chung`**. Never delete the
   item: *"this once had to be done"* is exactly what the next session needs to know.
4. New work discovered → append an item. Blocked on the customer → put the question number in
   `no_confirm` and say so to the user; do **not** decide it (rule 9, ROUTING §8).
5. `make kb` to regenerate the read surface.

### Checking — after several agents have written

Dispatch `progress-reviewer` (read-only). It catches what a hook cannot: an item claiming
`xong` whose evidence does not open, a module silent while its code moved, a `no_confirm`
pointing at a question the customer has since settled.

## WHAT IS ENFORCED, AND WHAT IS NOT

Stated plainly, because a guard that is believed to check more than it does is worse than no
guard — that failure has already cost this repository five patches.

| Enforced by `hooks/progress_guard.py` (BLOCK) | Not enforced |
|---|---|
| Hand-editing the generated `tien-do.md` | **Which agent** writes which module — the hook cannot see the agent's identity |
| A module name that is not a directory on disk | Whether `viec` describes the work honestly |
| Broken JSON, missing keys, an unknown `trang_thai` | Whether `bang_chung` actually proves anything |
| `xong` with an empty `bang_chung` | |
| A duplicate `id` inside one file | |
| `no_confirm` pointing at a non-existent or already-`DECIDED` question | |
| **An existing item disappearing from the file** | |
| Ending a session that changed a module's code without updating its ledger (Stop) | |

The unenforced column is `progress-reviewer`'s job, and it **reports** — it does not fix.

---

## REFUSALS

- **Do not write an empty item to clear the Stop gate.** Changed nothing worth recording? Say
  that sentence out loud and stop.
- **Do not delete another agent's item**, even one that looks wrong. Report it.
- **Do not copy the text of an open question here** — the number is the link (rule 9 #2).
- **No personal data, no secrets**, not even in an example (rules 3 and 8).
